FreddAId | ProActive

Full-stack developer · Sales Factory

An AI assistant for B2B sales teams. Instead of digging through hundreds of internal documents, users ask a question in plain language and get an answer grounded in their own company data. The platform also generates brand and competitor reports on a schedule.

  • React
  • TypeScript
  • Python
  • Flask
  • Azure
  • LangGraph
  • Cosmos DB

Technical detail and my contribution

The product lives across three repositories that make up one system: the web application, the AI orchestrator, and the Azure RAG infrastructure underneath.

1 · Web application

React 18 + TypeScript frontend (Vite) with a Flask backend organised by domain. AI chat with file attachments, a data-analyst mode and speech synthesis; per-organisation knowledge management; scheduled reports delivered by email; team, role and subscription administration.

  • Migrated endpoints from the external orchestrator into the local backend (settings, invitations, current user) to cut latency and get proper error handling.
  • Redesigned the subscription plans page and added in-app alerts for Stripe billing problems.
  • Built the split-screen analysis panel with resizable panes so a document and the chat are visible at once.
  • Set up the end-to-end test suite in Cypress covering onboarding, reports, knowledge sources, plans and team management.
  • Per-organisation file limits, loading and error states for the service status check, sidebar active-section highlighting, and bundle size cleanup.
  • Multiple web design creations

2 · AI orchestrator

Azure Functions in Python driven by LangGraph: query rewriting, augmentation with organisational context, tool selection (document search, data analysis, web scraping) and response generation streamed in real time. When intent is ambiguous the orchestrator pauses and asks for clarification instead of guessing (human-in-the-loop).

  • Implemented the job scheduler that automatically produces competitor and product analysis reports, with unit test coverage.
  • Refactored Azure Storage URL handling, including URL normalisation and a fix to the validation pattern.
  • Hotfixed data-type mismatches and a report generation failure in production.

3 · Azure RAG infrastructure

Built on Microsoft's open-source GPT-RAG accelerator: document ingestion and vectorisation, semantic retrieval with Azure AI Search, and Bicep deployments in either a simple or a zero-trust network setup.

  • Worked the infrastructure-as-code layer: Function App roles and permissions, Cosmos DB access for the reporting module, new containers, Event Grid wiring and log retention policies.
  • Synced OpenAI and AI Search API versions and cleaned up Bicep templates.

VibeWaggler

Full-stack developer · small team, built from scratch

Businesses with several locations get reviews scattered across Google and Yelp. VibeWaggler pulls them into one inbox, tracks how customer sentiment shifts over time and drafts replies with AI. Each company only ever sees its own data.

  • React
  • TypeScript
  • Supabase
  • PostgreSQL
  • Deno
  • Terraform
  • AWS
  • Claude API
Technical detail and my contribution

Multi-tenant platform: React 18 + TypeScript with shadcn/ui and TanStack Query on the front, Supabase (Postgres, Auth and Deno Edge Functions) as the backend, and delivery through AWS S3 + CloudFront managed with Terraform. Around 65 of my commits shipped to production, across every layer.

  • Inbox and navigation: new protected routing system, stable server-side pagination and selection that survives page changes. This was the product's first release to production.
  • Role-based access: a landing router that sends each user to the right flow based on their role and onboarding state, including logic to resume an interrupted setup.
  • Users and organisations: full user CRUD, email invitations with an acceptance and set-password flow, organisation switching, and tenant isolation enforced at the database level.
  • Dashboards on real data and AI: replaced all mock data with real Postgres queries across four dashboards (sentiment, monthly tracker, location deep dive and overall pulse), with unified filtering, index-effectiveness checks, and Claude-generated insights backed by caching and a per-plan quota.
  • Per-location permissions: a manager can be scoped to a subset of locations, enforced by row-level security in Postgres.
  • Subscription limits: active-location caps tied to the Stripe plan, checked during onboarding and in location management.
  • QR codes: per-location codes that send customers straight to the review flow, with platform URL derivation covered by property-based tests.
  • MCP server: an Edge Function exposing tools so external AI assistants can query reputation metrics.
  • Embeddable widget: a one-line snippet (~6 KB, no dependencies) that renders a carousel of curated reviews on the client's own site, using shadow DOM, full keyboard and screen-reader support, and anonymous reads locked down to six fields.
  • Infra and CI/CD: two Terraform stacks and GitHub Actions deploys over OIDC with no long-lived credentials, split across migrations, Edge Functions and frontend.

ScoopWaggler

Design and build

When someone asks ChatGPT or Google about a product, does your brand show up in the answer? ScoopWaggler measures it: it queries four AI platforms, crawls the website, and returns a 0–100 score with a diagnostic report of what to fix. Under two minutes end to end.

  • Python
  • FastAPI
  • React
  • AWS Lambda
  • Step Functions
  • DynamoDB
  • Terraform
Technical detail and my contribution

Serverless architecture on AWS: API Gateway → orchestrator Lambda → four AI platform audits in parallel (30 prompts each) alongside a technical site crawl → scoring engine → PDF and web report → email notification.

  • Composite score weighted per platform (Google, OpenAI, Perplexity, Claude) with automatic weight redistribution when one platform fails.
  • Five dimensions per platform: brand recognition, market competition, technical visibility and sentiment.
  • Competitive index that surfaces the top three rivals from the AI responses at no extra API cost.
  • Technical crawl of up to 20 pages with httpx: schema.org, llms.txt, AI bot rules, server- vs client-rendered detection and Core Web Vitals.
  • Pure, deterministic scoring engine with no side effects and unit tests per sub-function.
  • Constraints that shaped the design: a target cost of about $1.10 per report and sub-105s latency, which pushed the crawl and AI audits to run concurrently with per-platform caching.
  • Infrastructure as code in Terraform with separate environments, Cognito authentication and branch-based continuous deployment in GitHub Actions.

03 About

I'm Edgar Zambrano, a full-stack developer. I move comfortably between frontend and backend, and I'm drawn to the point where the product meets the infrastructure: something working on a developer's machine is fine, but the interesting part is making it work in production, for real users, without surprises.

My recent work has been mostly multi-tenant SaaS platforms with AI built in: conversational assistants grounded in a company's own documents, automated report generation and analytics dashboards. I also handle the less visible side: tenant data isolation, permissions, per-plan limits, automated tests and reproducible deployments.

I write code with the next reader in mind. I prefer pure, testable functions, clear module boundaries and infrastructure declared in files rather than clicked together by hand.
